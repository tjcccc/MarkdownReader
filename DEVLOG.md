## 2026-07-26

- Release: cut `0.3.0` — minor bump over 0.2.1. New user-visible capability (per-block language tag and copy button on fenced code), rounded code styling at both scales, inline-code padding, and three rendering fixes. One known issue ships with it, recorded below and in the README: the thin white seam across code blocks is still unresolved.
- Fixed: an inline-code span that wraps inside an indented list item painted a stray highlighted strip across the leading indent of the continuation line. Cause is AppKit drawing, not our attributes — `NSLayoutManager` builds each fill rect from the *line fragment* rect (left edge = container edge) rather than the *used* rect (left edge respects `headIndent`), so the indent got filled.
- Fix in `SelectableMarkdownView.swift` only: new `IndentAwareBackgroundLayoutManager` overrides `fillBackgroundRectArray(_:count:forCharacterRange:color:)` and clamps each rect's left edge to the enclosing line's used rect. `drawBackground(forGlyphRange:at:)` is overridden solely to capture the draw origin, since fill rects arrive origin-offset while used rects are in container coordinates. Rects with no matching line pass through unclamped rather than being dropped.
- Inline code now gets 2pt of horizontal padding on each side. Attributed strings have no padding attribute, so the same override inflates the fill rect; runs are tagged with a custom `.inlineCodeSpan` key in the renderer so block-level fills (quotes, fenced code) are excluded. Padding is applied *after* the indent clamp, so a wrapped span keeps the same inset on its continuation lines. Vertical padding was left alone — the fill already spans the line height, and inflating it would collide with neighbouring lines.
- Selection safety: NSTextView routes selection highlighting through the same primitive, and a selection band *should* cover the indent. The override therefore applies the **left** clamp and the inline-code treatment only when the fill color matches the `.backgroundColor` attribute at the range start. (Superseded in part later the same day: the **height** clamp below deliberately does apply to selection fills too, so selection no longer takes an entirely unmodified `super` path.)
- The view now builds an explicit TextKit 1 stack (`NSTextStorage` → custom layout manager → `NSTextContainer` → `ReadingTextView(frame:textContainer:)`). Previously the stack was implicit and only fell back to TextKit 1 lazily, when `layoutManager` was first touched during image hit-testing.
- Rounded corners, both scales: inline code chips are now drawn by the override as rounded rects (radius 4) instead of by `super`'s square fill; fenced code blocks use a new `RoundedTextTableBlock` (an `NSTextTableBlock` subclass overriding `drawBackground(withFrame:in:characterRange:layoutManager:)`, radius 8), since `NSTextBlock`'s own background drawing is always square. Block quotes were left square — not part of the request.
- Fenced code blocks gained a language tag and a copy button, sitting in a reserved strip at the top of the box (`CodeBlockMetrics.headerHeight`, added as extra `.minY` padding on the cell so the controls can never overlap a long code line). They're `CodeBlockHeaderView` overlays on the text view, not text, so they stay out of document selection and copied text. The tag is omitted when the fence carries no language hint; the button copies that block's source and flips to "Copied" for 1.5s.
- Renderer now tags each code block's characters with `.codeBlockInfo` (language + source); the view enumerates that attribute, and repositions the overlays from layout geometry in `layout()`.
- Thin white seam reported across a code block, just under the language tag.
